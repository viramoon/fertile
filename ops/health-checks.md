# 健康检查设计

finance（trader / collector / api）和 web 提供 /healthz，响应格式、选择 live / ready 的方式及端口 TBD，由实现 issue 确定。frontend 不是服务，健康检查经 web 的静态页面与资源验证。

| 检查 | 含义与失败影响 |
| --- | --- |
| live | 进程存活、能响应基本检查；不能据此判断可交易 |
| finance ready | Gateway 已认证、订阅和数据水位有效、行情新鲜、订单状态可信且对账完成；失败暂停开新仓 |
| collector ready | 数据源和订阅有效、catalog 可写、数据新鲜，不能用进程活着掩盖停更 |
| api ready | 查询依赖可用、关键状态与数据新鲜；失败不能拖停交易核心 |
| web ready | PostgreSQL、finance 关键依赖和匹配的静态资源可用；写依赖故障不得盲重试 |
| 公网端到端 | 从公网域名访问页面、静态资源和受控只读 API，核对内容与版本；本地返回 200 仍可能公网 502 / 530 |

外部探测与本地结果都记录时间、tag、延迟、错误类型和来源。TBD：域名、探测路径、频率、连续失败阈值和恢复目标，由运维验证确定。公网探测不发真实订单、不将展示可达等同交易 ready；故障恢复后还需新鲜度和对账验证。
